# Бот кофейни «Fade In»

Telegram-бот вымышленной кинокофейни. Отвечает на вопросы про меню, афишу и правила брони, принимает бронь столика. Ответы даёт модель через OpenRouter, бронь проверяет код.

## Файлы

| Файл | Зачем |
|---|---|
| `bot.py` | сам бот: Telegram, вызов модели, диалог брони |
| `system_prompt.md` | роль, правила, формат ответа и три few-shot примера в `<примеры>` |
| `menu.md` | единственный источник фактов: меню, цены, афиша, правила брони |
| `booking_prompt.md` | промпт, который достаёт из сообщения гостя поля брони в JSON |
| `booking_rules.py` | проверки полей брони и разбор JSON от модели |
| `test_cases.md` | 5 сообщений гостя, ответы до и после примеров, пример JSON |

## Запуск

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env   # впишите TELEGRAM_BOT_TOKEN и OPENROUTER_API_KEY
.venv\Scripts\python bot.py
```

## ДЗ 9: что сделано

**Few-shot примеры.** В `system_prompt.md` в блоке `<примеры>` три примера: обычный вопрос (цена рафа), вопрос без ответа в данных (парковка, ответ с пометкой `[уточнить]`) и вежливый отказ (реферат). Под блоком оговорка, что факты из примеров брать нельзя, только из меню.

**Бронь через JSON.** Если гость пишет про столик одним сообщением, модель по `booking_prompt.md` возвращает JSON: `intent`, `date`, `time`, `guests`, `name`, `phone`, `missing`. Дальше работает код: `parse_json_object` достаёт объект из ответа (даже если модель обернула его в ```), `apply_extracted` проверяет каждое поле теми же правилами, что и пошаговая бронь. Что не прошло проверку или не названо, бот спрашивает по одному полю. Если JSON не разобрался, делается вторая попытка, потом бот просит написать заявку заново.

## Выводы

1. **Примеры сильнее всего влияют на формат и тон, а не на факты.** Факты держит меню и правила: на вопрос про Wi-Fi модель не стала выдумывать ответ и до примеров. Зато после примеров ответы стали короче и «в роли»: вежливый отказ уложился в одно предложение, а на просьбу посоветовать фильм бот назвал два сеанса вместо четырёх.

2. **Модель копирует образец почти дословно.** Ответ про Wi-Fi повторил пример про парковку: «в сценарии про … ни слова, так что гадать не буду». Для одного вопроса это красиво, для диалога однообразно. Лучше, чтобы каждый пример отличался формулировкой, или чтобы примеров было больше трёх.

3. **Примеры не заменяют правила.** Ответ про фильм всё равно вышел с «нолановским лабиринтом» и «французским нуаром», которых в меню нет, и с названием напитка не так, как в меню. Правила проверяют лучше, чем образцы, поэтому они остаются в промпте, а примеры только поддерживают тон.

4. **Для брони JSON надёжнее, чем болтовня.** Когда я прогнал сообщение про бронь через обычный чат, бот пообещал «проверить свободные места», а такой проверки в коде нет. Через JSON всё честно: модель только вытаскивает поля, а решает код. На заявке «23:30 на 12 человек, телефон 8701123» модель вернула все поля заполненными, и код всё равно отклонил время, число гостей и телефон. Верить `missing` от модели нельзя, поля надо проверять самим.

5. **Выборка маленькая.** Все ответы в `test_cases.md` получены на одной бесплатной модели при `temperature=0`. Для других моделей и для температуры 0.4 из бота результат может отличаться. Пять сообщений мало, чтобы доказать улучшение, но достаточно, чтобы увидеть направление.
